# Команды проверки

Список собран из того, что реально есть в проекте: `requirements.txt`,
`.github/workflows/preflight.yml`, `deploy.sh`, `preflight.py`.
Манифестов `pyproject.toml`, `setup.py`, `tox.ini`, `pytest.ini`, `Makefile`,
`setup.cfg` в проекте **нет**.

| проверка | команда | есть? |
|---|---|---|
| установка зависимостей | `pip install -r requirements.txt` | да |
| синтаксис всех файлов | `python -m compileall -q -f -x '(\.venv\|__pycache__)' .` | да (в CI и `deploy.sh`) |
| предполётные проверки (проводка) | `python preflight.py` | да |
| проверки поведения | `python selftest.py` | да (с 28.08.2026, в CI и `deploy.sh`) |
| запуск проекта | `python main.py` | да |
| тесты (`pytest`, `test_*.py`) | — | **не найдено** (их роль частично закрывает `selftest.py`) |
| типизация | — | **не найдено** |
| линтер | — | **не найдено** |
| сборка | — | **не найдено** (пакет не собирается, код едет файлами) |

Ключ `-f` у `compileall` обязателен: без него Python считает годной ранее
скомпилированную копию, и сломанный файл проходит мимо проверки.

## Что именно проверяет `preflight.py`

Восемь проверок, по порядку. Сети и ключей не требуют; боевую базу не
трогают — `main()` первым делом уводит `DB_PATH` во временную папку.

| проверка | что сверяет |
|---|---|
| `check_imports` | грузятся ли все модули пакетов `services`, `handlers`, `database`, `jobs` — ловит имя, забытое в re-export |
| `check_models` | `config.AVAILABLE_MODELS` ↔ раскладка кнопок в `panel_main.py` |
| `check_providers` | список провайдеров |
| `check_tables` | таблицы `_create_schema` ↔ `reset_db.USER_TABLES` |
| `check_ranks` | звания викторины |
| `check_callbacks` | кнопки, найденные в панелях, ↔ ветки роутера |
| `check_panels` | все панели собираются и влезают в лимиты Telegram (4096 символов, 100 кнопок) |
| `check_handlers` | обработчики регистрируются, число групп |

правки):

## Что именно проверяет `selftest.py`

Заведён 28.08.2026. Отвечает на вопрос «правильно ли считает», тогда как
`preflight` — на «запустится ли». Сети и ключей не требует, боевую базу не
трогает (уводит `DB_PATH` во временную, как preflight).

| проверка | что сверяет |
|---|---|
| `check_money` | стоимость запроса к Qwen, DeepSeek, Xiaomi и за картинку, включая кривые ответы API: кэш-полей нет; кэша больше, чем всего входа |
| `check_price_list` | сами цены в `config` против сверенного прайса провайдеров |
| `check_mute_tag` | разбор `[МУТ:секунды]`: потолок, регистр, латиница, пометка в размышлениях, мусор внутри пометки |
| `check_permissions` | запрет по умолчанию, право на каждый вид кнопки, иерархия «кто над кем» |
| `check_thoughts` | `<thought>` не доезжает до чата ни одним путём, включая аварийную отправку; тумблер мыслей; исключение «ответ из одних размышлений» |
| `check_long_answers` | смещения разметки в UTF-16 не вылезают за текст; длинный ответ режется и влезает в лимит; при нарезке ничего не теряется и разметка есть во ВТОРОЙ части |
| `check_wait_budgets` | перебор моделей укладывается в потолок (личка и группа), первой попытке время не урезается, человек получает заглушку |

**Эталон исправного прогона (28.08.2026):**

```
деньги      — 14 проверок
прайс       — 33 цены
мут         — 17 проверок
права       — 23 проверки
мысли       — 18 проверок
разметка    — 132 проверки
потолки     — 17 проверок
```

⚠️ Число у разметки ПЛАВАЕТ и это нормально: каждое выделение в каждой части
считается отдельно, а частей столько, на сколько библиотека разрезала текст.
Резко упало до единиц — значит нарезка перестала работать, а не «стало
меньше проверок».

⚠️ `check_wait_budgets` подменяет ВРЕМЯ и СЕТЬ внутри `services/gemini.py`
(поддельные часы, каждая «зависшая» модель двигает их на свой таймаут).
Настоящие часы ждать нельзя — проверка гоняется на каждой выкатке. Всё
подменённое возвращается в `finally`; трогать модуль после неё безопасно.

⚠️ **ПОЧЕМУ ПРАЙС ПРОВЕРЯЕТСЯ ОТДЕЛЬНО** — не дублирование, а закрытая дыра.
`check_money` берёт цены из `config`, поэтому к САМИМ ценам слепа: меняются
обе стороны сразу, и всё «сходится». Проверено живым опытом в день заведения:
нарочно занижённая вдвое цена Qwen прошла мимо всех проверок. Отсюда второй
список — с числами, зашитыми в `selftest.py`. Списывать его из `config`
автоматически НЕЛЬЗЯ: это вернёт ту же слепоту.

⚠️ **ПРОВЕРКА, КОТОРАЯ НИЧЕГО НЕ ЛОВИТ, ХУЖЕ ОТСУТСТВИЯ ПРОВЕРКИ** — она
создаёт ложное спокойствие. Добавил новую — сломай проверяемое место нарочно
и убедись, что она покраснела И назвала, ЧТО именно разошлось. Все семь групп
так проверены в день заведения; список поломок, которыми их испытывали, —
в `history.md` за 28.08.2026.

## Чего проверки НЕ ловят

Это важнее списка того, что они ловят.

`preflight` не знает:

- **Поведение.** Тот ли текст уходит пользователю, работает ли кнопка после
  нажатия — ничего этого он не проверяет.
- **Работу с сетью и моделями.** Он намеренно никуда не ходит.
- **Реальную базу.** Работает на пустой временной.
- **Кнопки с `callback_data`, собранной f-строкой с переменной в начале.**
- **Тексты, длину сообщений в рантайме, разметку.**

`selftest` не знает:

- **Как части соединены.** Он проверяет функции ПО ОТДЕЛЬНОСТИ. Ошибку вида
  «обе части верны, а соединены неправильно» не увидит.
- **Всё, что требует живого Telegram** — отправку, клавиатуры, апдейты.
- **Всё, чего в нём просто нет.** Покрыты: деньги, пометка мута, права,
  размышления, разметка длинных ответов, потолки ожидания. НЕ покрыты:
  альбомы, ключи суток и недели, отбор статей базы знаний, антиспам,
  звания викторины, приветствие новичков.

Значит, ручной прогон после правки поведения никуда не делся: открыть
затронутый экран, нажать затронутую кнопку, отправить затронутый тип
сообщения. Список затронутого даёт
`python .claude/skills/project-map/scripts/impact.py <имя>`.

## Скрипты этой карты

```
python .claude/skills/project-map/scripts/map.py                 # вся таблица файлов
python .claude/skills/project-map/scripts/map.py --hubs          # на чём держится проект
python .claude/skills/project-map/scripts/map.py --module <файл> # подробности по файлу
python .claude/skills/project-map/scripts/impact.py <имя>        # кого заденет правка имени
python .claude/skills/project-map/scripts/impact.py <имя> --full # со всеми строками
```

Читают только код, ничего не пишут и никуда не ходят. Папку
`.claude/worktrees/` пропускают — там копии старых версий проекта.
