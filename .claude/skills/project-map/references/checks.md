# Команды проверки

Список собран из того, что реально есть в проекте: `requirements.txt`,
`.github/workflows/preflight.yml`, `deploy.sh`, `preflight.py`.
Манифестов `pyproject.toml`, `setup.py`, `tox.ini`, `pytest.ini`, `Makefile`,
`setup.cfg` в проекте **нет**.

| проверка | команда | есть? |
|---|---|---|
| установка зависимостей | `pip install -r requirements.txt` | да |
| синтаксис всех файлов | `python -m compileall -q -f -x '(\.venv\|__pycache__)' .` | да (в CI и `deploy.sh`) |
| предполётные проверки (проводка) | `python preflight.py` | да |
| проверки поведения | `python selftest.py` | да (с 28.08.2026, в CI и `deploy.sh`) |
| запуск проекта | `python main.py` | да |
| тесты (`pytest`, `test_*.py`) | — | **не найдено** (их роль частично закрывает `selftest.py`) |
| типизация | — | **не найдено** |
| линтер | — | **не найдено** |
| сборка | — | **не найдено** (пакет не собирается, код едет файлами) |

Ключ `-f` у `compileall` обязателен: без него Python считает годной ранее
скомпилированную копию, и сломанный файл проходит мимо проверки.

## Что именно проверяет `preflight.py`

Девять проверок, по порядку. Сети и ключей не требуют; боевую базу не
трогают — `main()` первым делом уводит `DB_PATH` во временную папку.

| проверка | что сверяет |
|---|---|
| `check_imports` | грузятся ли все модули пакетов `services`, `handlers`, `database`, `jobs` — ловит имя, забытое в re-export |
| `check_models` | `config.AVAILABLE_MODELS` ↔ раскладка кнопок в `panel_main.py`; все ЧЕТЫРЕ очереди подстраховки ссылаются на существующие модели — `FALLBACK_MODEL`, аудио, видео и `PROACTIVE_MEDIA_CHAIN` (последняя добавлена 08.09.2026, до того не сверялась вовсе); у моделей видео-очереди есть поле `video` |
| `check_providers` | список провайдеров |
| `check_tables` | таблицы `_create_schema` ↔ `reset_db.USER_TABLES` |
| `check_ranks` | звания викторины |
| `check_callbacks` | кнопки, найденные в панелях, ↔ ветки роутера |
| `check_panels` | все панели собираются и влезают в лимиты Telegram (4096 символов, 100 кнопок) |
| `check_handlers` | обработчики регистрируются, число групп |
| `check_web` | адреса сайта `web/routes.py::ROUTES` ↔ собранное приложение, и каждый адрес «owner» правда закрыт входом |

## Что именно проверяет `selftest.py`

Заведён 28.08.2026. Отвечает на вопрос «правильно ли считает», тогда как
`preflight` — на «запустится ли». Сети и ключей не требует, боевую базу не
трогает (уводит `DB_PATH` во временную, как preflight).

| проверка | что сверяет |
|---|---|
| `check_money` | стоимость запроса к Qwen, DeepSeek, Xiaomi и за картинку, включая кривые ответы API: кэш-полей нет; кэша больше, чем всего входа |
| `check_qwen_quota` | КВОТА QWEN НА ОБОРВАННОМ ОТВЕТЕ (18.09.2026): гоняется настоящий `_openai_stream_request` на поддельных часах и поддельной сети — поток шлёт куски и «зависает» за потолком `GEMINI_STREAM_DEADLINE`. Обрыв обязан стать таймаутом (иначе не сработает подстраховка) и списать ОЦЕНКУ токенов по знакам; отчёт о токенах уже пришёл — оценка не списывается (иначе двойной счёт); у чужих провайдеров не считается вовсе (проверяется ВОЗВРАТ функции, а не остаток Qwen — см. предупреждение ниже); пустой обрыв списывает хотя бы отправленный контекст. Плюс срок квоты: разбор ввода «66614 19.10.2026» (и отказ от мусора вместо даты) и показ приписки «квота до …» на экране «Счета и квоты». ПИСЬМА О КВОТЕ (19.09.2026): `spend_qwen_tokens` отдаёт пару «было → стало» (квоты нет — пустоту); переход через ноль и через `config.QWEN_QUOTA_WARN_TOKENS` приносит РОВНО ОДНО письмо, следующий ответ за чертой — ни одного; границы «ровно дошли до черты» и «уже стояли на черте»; оба порога разом — одно «кончилась»; в письме имя модели, остаток, цены из прайса, остатки ДРУГИХ Qwen и строка «активная» только у активной. Оба пути списания гоняются по-настоящему: оборванный — через `_charge_broken_stream`, обычный — через всю очередь `_gemini_chat_request` с поддельным ответом Qwen. ⚠️ Письмо ловится подменой `_notify_admins` — настоящее ушло бы владельцу при каждой выкатке |

| `check_ai_mute_name` | МУТ ОТ БОТА ПОДПИСАН ЧЕЛОВЕКОМ (16.09.2026): гоняется настоящий путь выдачи `proactive._apply_mute`, поддельные только Telegram и получатели письма. ## Чего проверки НЕ ловят
