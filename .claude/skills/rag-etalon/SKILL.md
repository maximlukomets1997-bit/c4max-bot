# Эталонные статьи базы знаний (RAG) бота C4_Max

## Что это и зачем

База знаний бота — папка `knowledge/approved/` (по одному .md на статью, 1 статья = 1 чанк поиска).
Новости с wtmobile.com бот сам складывает в `knowledge/pending/` (сырые, со служебной шапкой-frontmatter).
Задача: переписать сырую новость о технике в «эталонную» статью и положить в `knowledge/pending/` на одобрение.
**Одобряет только Максим** — через панель /rag в боте (кнопка «✅ Одобрить в базу»). Ты статьи в approved не переносишь.

Образцы готовых эталонов (читать перед работой!):
- **Танк:** `knowledge/approved/Т-80УМ2.md` (рукописный золотой стандарт) и `ZTZ-99A.md`, `Ariete_WAR.md`, `Centauro_RGO.md`, `M1A2_SEP.md`, `Т-72Б3А.md` (сделаны по этой методике).
- **Корабль:** `knowledge/approved/HNLMS_Jacob_van_Heemskerck.md`.
- **Самолёт:** `knowledge/approved/Swift_F.1.md` (истребитель), `Washington_B.Mk.I.md` (бомбардировщик), `B-57B_Canberra.md` (бомбардировщик без турелей, два варианта курсового вооружения). Структура утверждена Максимом 19.07.2026 — см. раздел «Структура эталона — САМОЛЁТ» ниже.

## Источники ТТХ (по приоритету)

1. **Игровая карточка ТТХ из самой новости.** Парсер бота достаёт её сам:
   ```python
   import sys; sys.path.insert(0, r"D:\WORK\Main Project")
   from services.scraper import fetch_article, _HEADERS
   art = fetch_article("https://wtmobile.com/news/<номер>")  # url из frontmatter сырого файла
   art["stat_images"]  # список URL карточек: *_stat_ru.jpg — обычная, *_prem_stat_ru.jpg — премиум (ТТХ одинаковые)
   ```
   Скачать основную карточку (`stat_images[0]`, НЕ prem) через requests и прочитать числа через **Gemini vision** (прямой вызов `config.GEMINI_MODEL` с base64 картинки — см. пример в конце файла; имя модели брать ИЗ КОНФИГА, а не вписывать строкой: набор моделей меняется, зашитая строка молча перестанет работать). На карточке: тип юнита, ранг, скорость/задний ход, удельная мощность, масса, экипаж, пробитие (стартовым снарядом!), перезарядка, скорость поворота башни; у кораблей — экипаж полный/минимальный, время поворота, время наведения ракет и по каждому вооружению урон + перезарядка; у авиации — скорость на высоте, скороподъёмность, время виража, потолок, нагрузка на крыло, курсовое вооружение (снаряды × выстр/с).
2. **Вики большой War Thunder** (wiki.warthunder.com/unit/..., слаг искать веб-поиском «<танк> wiki.warthunder.com unit») — то, чего нет на карточке: названия и пробития снарядов, УВН (углы наводки), стабилизатор, особенности (КАЗ, подвеска). ⚠️ Скорости вики ЧАСТО врут относительно WTM — игровая карточка главнее.
3. **Скриншоты Максима из ангара** — финальная истина. У ИССЛЕДУЕМЫХ машин (ветки деревьев, не трофейные) карточек в новостях НЕТ — по таким писать цифры с вики и прямо просить Максима сверить/прислать скриншот.
4. **Текст самой новости** — сильные/слабые стороны, роль в бою, особенности (вышибные панели, ПРО, отличия от предшественника). Современных ракетных кораблей в большой WT нет — для них источники только карточка + текст.

Проверка честности парсера (по желанию/при сомнениях): скачать страницу новости напрямую и вытащить ВЕСЬ текст `div.news-container` без фильтров — сравнить. Парсер намеренно режет премиум-блоки и дисклеймеры (это нормально, для эталона они не нужны).

## Первая строка описания = тип техники (раздел в панели /rag)

Тип решает, в КАКОЙ РАЗДЕЛ попадёт статья: 🚜 наземная техника, ✈️ авиация, 🛥️ корабли, ⚓ подводные лодки,
📘 игровые механики (значки — решение Максима 2026-07-18). С 2026-08-12 панель /rag разложена по разделам:
на главном экране кнопка на каждый непустой тип со счётчиком, статьи — внутри. Значок стоит в заголовке раздела,
а не на каждой кнопке, как было раньше. Этот же тип управляет разделами справочника техники /ttx.

Тип определяется автоматически **по первой строке описания статьи** — той самой, где есть слова «в War Thunder Mobile»
(`detect_kind` в `services/knowledge_store.py`, значки и порядок групп — в `ARTICLE_KINDS` там же). Читается ТОЛЬКО эта
строка, а не весь текст: иначе корабль со словом «самолёт» в разделе тактики уехал бы в авиацию.

**Что это требует от тебя:** в первой строке ОБЯЗАН стоять тип техники словами — так, как он уже пишется в эталонах:
- наземная: «основной боевой танк (ОБТ)», «лёгкий танк», «истребитель танков», «БМП», «боевая машина поддержки танков», «зенитная самоходка (ЗСУ)»;
- авиация: «реактивный истребитель», «истребитель-бомбардировщик», «штурмовик», «бомбардировщик», «перехватчик»;
- корабли: «линкор», «линейный крейсер», «ракетный крейсер», «ракетный эсминец», «фрегат», «дредноут»;
- подлодки: «атомная подводная лодка» (слово «субмарина» тоже опознаётся).

Забудешь указать тип — статья уедет в раздел «📄 Без типа». Это не поломка, а видимый сигнал: раздел этот обычно пуст и
на экране не показывается вовсе, так что само его появление означает «в первой строке какой-то статьи нет типа» — зайди
и поправь. Отдельно помнить: «истребитель танков» — это НАЗЕМНАЯ машина, классификатор знает про этот подвох
(наземные обороты проверяются раньше авиационных), специально обходить формулировку не нужно.

Статьи об игровых механиках (КАЗ, детонация боеукладки, танкование ромбом) описания с «War Thunder Mobile» не имеют — они
автоматически получают 📘. Приставку «Игровая механика:» в заголовке панель на кнопке срезает, но в файле её оставлять как есть.

## Прозвища (первая строка статьи)

Формат первой строки — как в Т-80УМ2:
`<Имя> (игровые прозвища: <варианты через запятую>) — <страна> <тип> <ранг> ранга в War Thunder Mobile. <2–3 фразы сути>.`

Правила (все — решения Максима):
- Писать РОВНО «игровые прозвища:» (не «русские написания»).
- Без кавычек-ёлочек вокруг прозвищ.
- Обязательно кириллические написания и варианты слитно/через пробел: «зтз99а, зтз99, зтз 99».
- **ВАРИАНТЫ С ДЕФИСОМ НЕ ПИСАТЬ** — правило Максима, подтверждено 2026-08-13 (он вычеркнул «оплот-т» из
  BM Oplot-T, оставив «оплот, оплот т, бм оплот»).
  Как это работает на самом деле (проверено на `services/rag.py::_text_stems`): дефис у поиска ВНУТРИ слова,
  то есть «оплот-т» — отдельный токен, который совпадёт только с точно таким же написанием в вопросе, а
  «оплот т» распадается на «оплот» + «т». Поэтому дефисная форма не помогает написаниям без дефиса, а
  формы «оплот» и «оплот т» покрывают частые варианты; спросят «оплот-т» — сработает смысловой канал.
- Прозвища НЕ ВЫДУМЫВАТЬ. Источник — реальное общение: архив групп бота, только чтение.
  ⚠️ Архив живёт НА СЕРВЕРЕ. Домашняя `history.db` на ПК не обновляется с переезда бота (27.07.2026) —
  искать в ней значит смотреть прошлогодний снег:
  ```
  ssh c4max 'cd /home/c4bot/bot && sudo -u c4bot .venv/bin/python -c "
  import sqlite3
  con = sqlite3.connect(\"file:history.db?mode=ro\", uri=True)
  for r in con.execute(\"SELECT first_name, substr(text,1,120), created_at FROM group_messages WHERE lower(text) LIKE ? ORDER BY created_at DESC LIMIT 20\", (\"%зтз%\",)):
      print(r)
  "'
  ```
  Плюс интернет. Нет народного прозвища — вписать только варианты написания, прозвище добавится позже.
  Анонсы («Скоро в игре») в архиве всегда пусты: технику ещё не обсуждают, там будут только пересланные
  ботом тексты новостей — это нормальный ответ «прозвищ пока нет», а не повод искать дальше.
- Прозвища-«национальности» («китаец», «голландец») Максим НЕ одобряет.
- Техническая деталь: лексический канал поиска игнорирует слова короче 4 букв — «зтз» ловится только смысловым каналом; опора — полные формы. Известные примеры из чата: «умка» (Т-80УМ2), «т72», «тайп»/«тайпы» (японцы), «центауро»,
  «фает» (La Fayette), «кай200» (Ki-200 — японские машины серии Ki читаются как «кай»; оба вписал сам
  Максим 2026-08-13 вместо моих вариантов транслитерации).

## Структура эталона — ТАНК

```
# <Имя машины>            ← без «[Скоро в игре]» и прочих префиксов
<первая строка с прозвищами — см. выше>
## Характеристики (ТТХ)   ← таблица | Характеристика | Значение |
## Сильные и слабые стороны   ← два списка «Сильные/Слабые стороны <Имя>:»
## Уязвимые места и защита    ← список «Куда пробивать <Имя> (зоны ваншота):» + абзац «Защита: …»
## Тактика и роль в бою       ← абзац: роль, как играть, чего избегать
```

Строки таблицы ТТХ (что есть — по данным): Орудие (калибр, название, стабилизатор, автомат заряжания); Перезарядка (КД орудия); Топовый ОБПС (лом) — имя + пробитие; Второй ОБПС; Кумулятивный; Топовый ПТУР (ракета) — имя, тандемный?, пробитие; УВН вниз (с пометкой «плохие/отличные углы склонения»); УВН вверх; Экипаж; Макс. скорость вперёд/назад; Масса; Удельная мощность; Скорость поворота башни; Уникальная особенность (КАЗ, вышибные панели, гидроподвеска…).

## Структура эталона — КОРАБЛЬ

```
# <Имя корабля>
<первая строка с прозвищами — см. выше>
## Характеристики (ТТХ)   ← сюда ВСЁ вооружение целиком
## Сильные и слабые стороны
## Тактика и роль в бою
```

Отличия от танка: в таблице первая строка «Тип» (Ракетный эсминец, страна, ранг); залп целиком (сколько и каких ракет); по каждому вооружению урон + перезарядка; ПРО/ПВО; артиллерия (или «нет»); контрмеры/дымы/РЭБ; скорость, время поворота, время наведения ракет, экипаж (полный/минимальный). В тактике — абзац «чем опасен противнику / как противостоять».

⚠️ **ОТДЕЛЬНОГО РАЗДЕЛА «Вооружение» У КОРАБЛЕЙ НЕТ** (решение Максима 2026-08-04, применено ко всем 24 корабельным статьям): все ТТХ вооружения живут В ТАБЛИЦЕ и только там. Раньше раздел дублировал таблицу словами — те же урон и перезарядка по второму разу, и в карточке `/ttx` вооружение показывалось дважды подряд. Нашёл факт, которому не хватает места в таблице (назначение ракеты, схема башен, наличие дымов) — добавляй его СТРОКОЙ или хвостом к строке через «;», а не новым разделом. Раздел «Вооружение и стрельба» остаётся ТОЛЬКО у авиации: там это не перечень, а как именно стрелять. Сопоставление строк карточки с ракетами из текста: правило «ПКР = строка с максимальным уроном, ЗУР — меньше, торпеды/ПЛУР — отдельные строки» (подтверждено Максимом на Хемскерке); спорное — сверять. Механику «у кораблей премиум заменяет стандартную версию» в статьи не включать.

Подтипы (выучено на пакете из 22 кораблей 2026-07-18):
- **Подводные лодки:** в таблице ТРИ скорости (на поверхности / перископная / под водой), запас кислорода, у ракет пометка, откуда пуск (из-под воды — Harpoon у Seawolf; с перископной глубины — Tomahawk у Astute, «Калибр» у Пр. 971). Тактика строится на цикле «сблизился под водой → перископ → залп → нырнул»; всплытие = максимальная уязвимость.
- **Артиллерийские корабли (акционные, ранги II–IV):** линкоры/крейсера эпохи Первой мировой, в большой WT их обычно нет. В таблице калибры по строкам карточки (главный, вспомогательные, ПВО, торпеды) с уроном и КД — с числом стволов и башен прямо в строке («восемь 343-мм орудий в четырёх башнях»).
- **Ракетные крейсеры (Bunker Hill, Long Beach, Пр. 1144):** «мастера залпа» — в тактике обязательно цикл «залп → укрытие на перезарядку».

## Структура эталона — САМОЛЁТ (утверждено Максимом 2026-07-19 на Як-23)

Больше всего данных для таблицы — на вики БОЛЬШОЙ War Thunder (wiki.warthunder.com), информация почти идентична WTM (Максим подтвердил). Карточка WTM даёт: тип юнита, ранг, курсовое вооружение (снаряды × число: боезапас, выстрелов/сек), число пилонов, экипаж, макс. скорость и высоту её достижения, потолок, время виража, скороподъёмность, нагрузку на крыло. Вики добавляет то, чего на карточке нет: предельную скорость разрушения (Max Speed Limit IAS), скорострельность в минуту, массу секундного залпа, разбег.

Строки таблицы ТТХ: Тип (Реактивный/поршневой истребитель/штурмовик/бомбардировщик, страна, ранг); Курсовое вооружение (пушки/пулемёты — калибр, число, боезапас, выстр/мин, секундный залп); Подвесное вооружение (бомбы/НАР/ПТУР по вариантам загрузки — или «нет (0 пилонов)»); Оборонительные турели (для бомберов — Ту-4, Washington); Макс. скорость (с высотой); Предельная скорость (разрушение, IAS) — с вики; Скороподъёмность; Время виража; Максимальная высота (потолок); Нагрузка на крыло; Лётный экипаж.

Разделы: `# Имя` → первая строка с прозвищами/типом/рангом/сутью → `## Характеристики (ТТХ)` → `## Сильные и слабые стороны` → **`## Вооружение и стрельба`** (авиазамена «Куда пробивать»: чем и как стрелять — баллистика, упреждение, длина очередей; для ударных — что вешать на пилоны и по каким целям) → `## Тактика и роль в бою` (как летать) + в конце **обязательный** абзац **«Как противостоять <имя>»** (что делать, если этот самолёт у противника — игроки спрашивают; формат: 2–3 конкретных совета через точку с запятой).

Классы: истребитель (бой за высоту/энергию), перехватчик (скорость+разгон, Як-23), штурмовик (подвесы по земле + пушки), бомбардировщик (бомбовая нагрузка + оборонительные турели, экипаж >1). У бомберов/штурмовиков строка «Подвесное вооружение» с вариантами загрузки обязательна.

## Что ВСЕГДА выкидывать

- Разделы «Способы получения», трофеи, чертежи, джекпоты.
- Премиум-блоки («Премиумная версия — это…», отличия премиума).
- «Историческую справку» (реальная история — не для базы).
- Дисклеймеры («*Характеристики предварительные…»).
- Служебную шапку-frontmatter (title/tag/url/date).
- Обрубки «Посмотреть характеристики снарядов…» (на сайте это кнопка).
- Раздел «Видеообзор» НЕ ставить, пока Максим не даст ссылки (появятся — как в Т-80УМ2: YouTube + TikTok).

## Файлы и финал

- Готовую статью писать в `knowledge/pending/<Имя_машины>.md` (подчёркивания вместо пробелов, скобки допустимы: `WZ1001(E)_LCT.md`).
- Сырой файл новости после переписывания УДАЛИТЬ из pending.
- Файлы в approved руками не менять без нужды; если поменял — индекс отстанет: Максим должен нажать «🔄 Пересобрать RAG» (или перезапустить бота — синк по mtime на старте). Бот обычно ЗАПУЩЕН — pending трогать безопасно, БД только read-only.
- В отчёте Максиму: что взял откуда, какие цифры под сомнением (просить сверить в ангаре), какие прозвища предположил. Максим — не программист: по-русски, простым языком, без кода.

## Быстрый чек-лист

1. Прочитал образец (Т-80УМ2 / Хемскерк / F-80C-10) и сырой файл (url в шапке).
2. Карточка ТТХ через парсер → Gemini vision → числа. Нет карточки (исследуемая техника)? → вики + пометка «сверить», просить скриншот.
3. Вики большой тундры: снаряды, УВН, предельная скорость, секундный залп.
4. Прозвища: архив групп + интернет; формат «(игровые прозвища: …)».
5. Собрал по структуре; выкинул мусор; проверил, что русские написания в тексте есть.
