# C4_Max — Telegram-бот по War Thunder Mobile

Бот-помощник с базой знаний по технике (танки, корабли), новостями с wtmobile.com,
викториной, антиспамом и админ-панелью.

## Запуск на новом хостинге

1. Скопировать `.env.example` в `.env` (или вписать те же переменные в панели
   хостинга — раздел «Config Vars» / «Переменные окружения»).
2. Заполнить как минимум `TELEGRAM_TOKEN` и `GEMINI_API_KEY`.
3. Установить зависимости:

   ```
   pip install -r requirements.txt
   ```

4. Запустить:

   ```
   python main.py
   ```

Больше ничего настраивать не нужно — база данных `history.db` создастся сама
при первом запуске.

## Что НЕ хранится в репозитории

| Файл | Почему |
|---|---|
| `.env` | живые ключи и токены |
| `history.db` | переписка реальных пользователей |
| `backups/` | ночные копии той же базы — те же живые данные |
| `.build` | метка сборки: какой коммит лежит именно на этой машине |
| `logs/`, `watchdog.log` | мусор времени выполнения |

При переезде на новый хостинг эти файлы переносятся отдельно, вручную.

## Структура

| Папка / файл | Что внутри |
|---|---|
| `main.py` | точка входа, сборка приложения |
| `config.py` | все настройки и переменные окружения |
| `jobs.py` | задачи по расписанию (новости, отчёты) |
| `handlers/` | обработка команд и сообщений, админ-панель |
| `services/` | модели, RAG, парсер новостей, антиспам, роли |
| `database/` | работа с историей диалогов |
| `knowledge/` | статьи базы знаний |
| `data/` | вопросы викторины |
| `preflight.py` | предполётные проверки перед выкаткой (зовёт `deploy.sh`) |
| `watchdog_local.py` | локальный сторож; на хостинге с автоперезапуском не нужен |

## Копии базы

Раз в сутки бот сам делает копию `history.db`: кладёт сжатый файл в `backups/`
(хранятся последние 7) и следом за суточным отчётом о расходах увозит её в
облако — Google Drive, папка `C4Max-Backups`, ничего оттуда не удаляется.
Владельцу в личку приходит строчка-доклад, сам файл — нет.

Копия по требованию — кнопка «💾 Копия базы» в `/adm`: присылает файл в чат и
заодно кладёт его в облако.

Облаком заведует сторонняя программа `rclone` (`services/cloud_backup.py`).
Ключ доступа выдаётся ей один раз, руками, и лежит на сервере в
`/home/c4bot/.config/rclone/rclone.conf` — через GitHub он не ездит, как и
`.env`. Пока rclone не настроен (например, на компьютере), бот возвращается к
старому поведению и шлёт файл в личку — ночи без копии не бывает.

Восстановление: распаковать `history-ГГГГ-ММ-ДД_ЧЧ-ММ.db.gz` любым архиватором
и положить получившийся файл на место `history.db` при остановленном боте.

## Проверки перед выкаткой

`python preflight.py` — загрузка всех модулей, сверка моделей с кнопками,
кнопок с обработчиками, таблиц со списком сброса и сборка каждой панели на
временной базе. Ни сети, ни ключей, ни боевой базы не требует; код возврата
1 означает, что выкатывать нельзя. То же самое делает `deploy.sh` при каждом
обновлении — не прошло, значит откат на прежнюю версию.

## Требования

Python 3.10+, зависимости — в `requirements.txt` (6 пакетов, все лёгкие).
Боту хватает ~60 МБ оперативной памяти.
